# AI-Tracker

**AI가 빠르게 일하는지보다, 맡긴 일을 좋은 결과로 마쳤는지 검토하는 로컬 대시보드입니다.**

AI 직원이라는 비유를 사용하되 에이전트 수·호출 수를 성과로 보지 않습니다. 사용자 지시, 공개 수행 기록, 산출물, 검증 근거와 수정 이력을 연결해 AI 사용의 품질을 높이는 것이 목표입니다. 장기적으로는 GPT/Codex에서 지시하고 이 화면에서 결과와 필요한 결정을 검토합니다. 모든 GPT 대화 수집이나 승인 실행이 이미 지원되는 제품은 아닙니다.

현재 React/TypeScript/Vite와 Node HTTP 서버로 만든 관측 전용 개발 버전입니다. 기본 화면에 가짜 업무를 넣지 않습니다. 개인 실행 기록을 포함하지 않는 공개 코드 저장소이며, 복제만으로 다른 사람의 Codex 업무를 볼 수 없습니다.

## 설치와 실행

필요 환경: Node.js 20.19 이상 또는 22.12 이상, npm, 이미 설치·인증된 호환 Codex CLI. 공식 App Server 스키마가 변경될 수 있습니다. 개발 검증 기준은 CLI `0.164.0-alpha.11.1`이며 다른 버전의 호환성은 확인해야 합니다. 앱은 새 인증이나 API 키 생성을 수행하지 않습니다.

개발할 때는 아래 명령 한 번으로 화면과 읽기 API를 함께 실행합니다. 사전 빌드는 필요 없습니다.

```sh
npm ci
npm run dev
```

브라우저에서 **http://127.0.0.1:5173** 을 엽니다. 화면 코드는 Vite가 자동 반영하고 `server` 모듈 변경은 Node watch가 API를 자동 재시작합니다. API 재시작 중에는 연결 상태가 잠시 미확인이 될 수 있으며 캐시는 다시 채워집니다. 종료는 실행 터미널의 Ctrl+C이며 함께 띄운 개발 API도 종료합니다.

개발 API 기본 포트는 4312입니다. 기존 4310 서버는 그대로 두며 포트가 사용 중이면 덮어쓰거나 임의로 종료하지 않습니다. 필요하면 `DEV_PORT=5174 DEV_API_PORT=4313 npm run dev`처럼 두 포트를 지정합니다. 개발용 Host·Origin 프록시도 해당 포트에 맞춥니다. 모든 바인딩은 127.0.0.1입니다.

수정 없이 빌드 결과를 실행할 때는 다음을 사용합니다.

```sh
npm run build
npm start
```

빌드 결과 주소는 **http://127.0.0.1:4310** 입니다. 이 방식은 자동 갱신하지 않습니다. 다른 노트북 접속·공개 배포·자동 시작은 구성하지 않습니다.

CLI는 `CODEX_BIN`, macOS 공식 앱의 번들 경로, PATH의 `codex` 순서로 선택합니다. 필요하면 다음처럼 **본인 컴퓨터의 경로**를 지정합니다. 실제 경로나 자격증명을 저장소에 기록하지 마세요.

```sh
CODEX_BIN="/absolute/path/to/codex" npm start
```

`PORT`는 `npm start`의 포트를 변경합니다. 개발 명령은 별도 `DEV_PORT`와 `DEV_API_PORT`를 사용합니다. `docs/prototype/*.html`은 합성 시안이며 실제 데이터를 확인하려면 개발 앱의 5173 주소를 사용하세요. 시안도 개발 서버의 `/docs/prototype/` 경로로 열면 HTML 변경을 자동 반영합니다.

## 현재 사용할 수 있는 것

- 결과 검토함: 관측된 업무의 최근 턴 최종 응답과 명시적 확인 문장 후보.
- 상세: **선택한 같은 턴**의 사용자 지시 → 공개 도구 수행 → 에이전트 최종 보고 → 검증 명령 근거. 긴 항목은 페이지 단위로 더 읽습니다.
- 과거 턴: 상세의 턴 선택과 ‘이전 턴 더 보기’. 현재 홈은 최신 턴 중심이며 전체 이력을 누적 분석하는 화면은 아닙니다.
- 사용량·실행 근거: 부모 업무 상세의 사용량 탭에서 선택 턴에 기록된 sub-agent ID별 사용량과 종료 관측을 확인합니다. 목록에 없는 실행도 공식 메타데이터 확인 후 조회하며 API 미제공·조회 오류를 구분합니다. API가 제공한 토큰, 선택 턴 시간, 로드한 도구 호출/실패/동일 입력 반복, 검증 명령. 미제공 값을 추정하지 않습니다.
- Sub-agent 실행: 부모 대화를 선택하면 전체 턴·항목 페이지에서 실제 하위 실행을 찾습니다. 일반 목록에 없는 실행도 공식 메타데이터로 확인하고 ID별로 중복을 제거합니다. 역할명 제한 없이 실행·종료 수, 사용량 제공 여부, 출처 근거와 실행 상세를 표시합니다. 미조회·부분 조회와 API 미제공을 0회/0 tokens로 간주하지 않습니다.
- 검색, 프로젝트/상태 필터, 상세 새로 읽기, 15초 목록 갱신, 연결 지연과 마지막 확인 시각.
- 네 종류 Hooks의 제한된 로컬 시험 수집기와 별도 시험 화면. 활성 훅·로컬 신뢰·실제 이벤트는 배포본에 포함하지 않습니다.

## 중요한 한계

**사용자 보고:** 진행 중인 대화가 보이지 않고 최신 대화만 보여 누적 추적이 부족합니다. 코드에 과거 턴 조회가 있다고 해서 이 문제가 해결된 것은 아닙니다. 현재 공급 범위와 화면 구조의 문제로 남겨두었습니다.

별도 App Server의 상태 DB 읽기와 15초 폴링이며, 다른 앱·클라우드의 모든 진행 상황을 실시간 구독하지 않습니다. notLoaded/idle, 연결 끊김, 오래된 기록을 업무 완료로 바꾸지 않습니다. 실행 종료는 품질 검증 완료와 다릅니다. 실제 공식 pending 승인 요청은 미연결이며 문장 후보는 현재 미해결 여부 미확인입니다. 승인은 원래 대화에서 처리합니다.

작업별 threadUsage가 null이면 토큰 미제공입니다. 스레드/모델 그룹 값과 선택 턴을 섞거나 부모·자식을 추정 합산하지 않습니다. 구독 한도는 계정 전체 참고값이며 실행 비용이 아닙니다. 임의 품질 점수·추정 비용·역할 순위는 없습니다.

이전 제한 시험에서는 두 하위 역할의 시작/종료·공개 결과를 관측했지만 부모 Stop은 수신되지 않았습니다. 네 종류 전체 수집 성공으로 보지 않으며 추가 시험은 보류 상태입니다. 개인 식별자·프롬프트·결과·스크린샷은 공개하지 않습니다.

## 검증

```sh
npm test       # 합성 데이터 단위·회귀 테스트
npm run build # TypeScript 검사 후 production 빌드
```

명시적 UI fixture: 빌드 후 `node test/fixture-server.mjs`로 127.0.0.1:4311을 엽니다. `/tmp/agent-dashboard-ui-mode.txt`의 empty/active/failed/question/long/ended/subagents/agent-usage 값으로 상태를 선택합니다. 모든 표시값은 합성이며 실제 업무가 아닙니다. 기본 실행은 fixture를 import하지 않습니다. 지연 응답 회귀 전용 서버는 `node test/race-fixture-server.mjs`이며 같은 4311을 사용하므로 동시에 실행하지 않습니다. 테스트 서버 중지도 Ctrl+C입니다.

공개 코드 검사: `npm run check:public`은 Git staged 내용의 금지 경로·개인 식별 흔적·비밀 패턴을 검사합니다. 자동 검사는 수동 staged diff 검토를 대체하지 않습니다. 테스트에서 사용하는 비밀 모양 문자열은 합성임을 표시합니다.
