# 현재 상태

이 문서는 공개 코드 기준을 설명한다. 로컬 개인 서버의 동작·데이터를 원격으로 보증하지 않는다.

## 확인된 구현

- React/Vite/TypeScript 화면 + Node 읽기 서버. localhost 고정, GET/Host/Origin 검사.
- 결과 검토함과 보조 업무 목록, 프로젝트/검색 필터. 최신 턴 요약을 중심으로 표시.
- 상세의 같은 턴 지시·공개 도구·최종 응답·검증 명령, 40항목 페이지 추가.
- 턴 목록 8개씩 조회, 선택·이전 턴 추가 읽기. 늦은 A 응답으로 선택 B가 덮이지 않도록 세대/요청 순서 검사.
- 실제 API 필드가 있을 때만 시간/모델/토큰/관계 표시. 반복 호출과 실패 근거를 구분. 내부 실행 필터와 비밀 마스킹.
- 제한 Hooks 수집기와 시험 화면. 네 종류 allowlist, 마커 등록 세션, 두 시험 역할 matcher, 로컬 14일 정책. 공개본은 활성 설정과 이벤트를 포함하지 않음.

## Sub-agent 실행과 사용량 — 대화 전체 대조

- 실제 진단에서 일반/보관 `thread/list`에 없는 하위 실행도 공식 `thread/read`로 읽을 수 있음을 확인했다. 역할명 필터 문제가 아니라 목록 기반 발견 방식과 최신 턴/항목 페이지만 보던 범위 문제가 원인이었다. 기존 합성 검증만으로 실제 누락 해소를 확인할 수 없었다.
- `Sub-agent 실행` 화면에서 부모 대화를 선택해 조회 가능한 전체 턴·항목 페이지를 탐색한다. 활동·협업 기록의 실제 ID를 중복 제거하고 메타데이터로 공개 하위 실행을 확인한다. 일반 대화 참조와 내부 실행은 sub-agent 개수에 넣지 않는다. 특정 역할명 제한은 없다.
- 대조 대상 대화의 공식 기록을 독립 집계하고 새 API·실제 브라우저의 실행 수/종료 수와 일치함을 확인했다. 동일 ID의 여러 종료 보고를 중복 실행으로 세지 않으며, 목록 미포함 실행도 상세를 열 수 있다. 실제 원문·ID·경로·화면 증거는 저장소에 남기지 않았다.
- 해당 실행들의 `account/usage/read`는 모두 threadUsage 미제공이었다. 이는 이용하지 않았거나 0 tokens라는 뜻이 아니다. 숫자 사용량 일치는 검증 불가이며 화면에 API 미제공으로 남긴다. 설치 CLI의 공식 스키마에도 threadUsage는 billing route가 있을 때만 제공하는 선택 값이다. 계정 합계나 부모 값을 자식 값으로 대체하지 않는다.
- 전체 대화 스캔은 최대 20개 턴 페이지·200개 항목 페이지·100개 실행을 읽는다. 실패/한도/미분류는 부분 조회로 표시하며 미조회/오류를 0회로 단정하지 않는다. 공식 메타데이터에서 공개로 확인한 실행만 메모리에서 상세 읽기 대상으로 등록한다. 캐시는 최대 20개 대화, 확인된 실행 ID는 최대 2000개이며 영구저장하지 않는다.
- 선택 턴의 기존 사용량 탭도 유지한다. 공식 응답 ID·숫자 검증, 갱신/상태 변경과 수동 재조회 시 캐시 무효화, null/오류 재시도를 제공한다. 활동 이벤트는 도구 호출 횟수에 더하지 않는다. Hooks 설정·실험 범위는 변경하지 않는다.
- 51개 합성 회귀와 TypeScript/Vite 빌드 통과. 회귀는 전체 턴/항목 페이지, 중복 종료, 부분 조회, 메타데이터 실패, 내부 실행 제외, 대화와 실행 범위 구분을 포함한다. 실제 검증은 개발 API와 5173 화면 기준이며 기존 production 4310 프로세스 재시작은 포함하지 않는다.

## 자동 갱신 개발 실행

- `npm run dev`로 Vite 화면(기본 5173)과 Node watch 읽기 API(기본 4312)를 함께 실행한다. 프런트 수정은 자동 갱신하고 서버 import 모듈 수정은 API를 자동 재시작한다. 사전 production 빌드는 필요 없다.
- 기존 4310 실행과 분리하며 포트 충돌 시 명시적으로 실패한다. `DEV_PORT`/`DEV_API_PORT`로 변경한다. Ctrl+C는 이 명령에서 만든 API와 Vite를 종료한다. 기존 관측 업무나 기존 4310 서버를 종료하지 않는다.
- 개발 프록시는 정확한 개발 UI Origin만 API Origin으로 변환하며 외부 Origin과 cross-site 증거는 보존한다. 모든 서버는 localhost에만 바인딩한다.
- 45개 테스트와 TypeScript/Vite 빌드 통과. 개발 화면·Vite 갱신 클라이언트·API proxy의 HTTP 200, 개발 Origin HTTP 200, 외부 Origin HTTP 403을 확인했다. 서버 모듈 파일 변경 후 Node watch의 실제 API 재시작 로그도 확인했다. 프런트 상태 보존을 보장하는 React Fast Refresh 플러그인은 추가하지 않았으며 Vite가 필요에 따라 전체 페이지를 갱신한다.

## 해결되지 않은 사용자 문제보고

| 사용자 경험 | 코드에서 확인한 사실 | 판정 |
|---|---|---|
| 진행 중인 대화가 안 보임 | 별도 App Server의 저장 DB 읽기. 전체 앱/클라우드 런타임 구독은 없음 | 미해결. 현재 공급 범위와 실시간 노출 가능성 확인 필요 |
| 최신 대화만 보여 누적 추적이 부족 | 홈은 최신 턴 요약. 상세에 과거 턴 선택/페이지 API는 있음 | 전체 이력 UX·누적 근거 모델은 미구현. 과거턴 API 존재로 해결 처리 금지 |
| 역할별 품질·위임 가치 판단이 필요 | 관계가 있는 실행 사례와 호출 근거만 제공 | 품질 기준/사용자 평가/산출물 채택/재작업 연계는 기획 단계 |

## 수집 범위·누락

App Server: thread/list(useStateDbOnly:true) 비보관 최대1000개, 메타데이터 최대100개/5분 캐시, 최근24개 턴 요약/60초 캐시. 목록15초 폴링, 상세는 사용자 요청 시 읽는다. 큰 이력의 누락/페이지 여부를 보존해야 한다. 등록 프로젝트 전체나 GPT의 모든 작업 수집을 의미하지 않는다.

상세는 thread/turn/items 지원 읽기 경로만 쓴다. threadUsage=null을 관측한 경우 토큰 미제공이다. 부모·자식/턴 사용량 범위 추정과 비용 환산을 하지 않는다. 공식 pending 승인 목록은 미연결이다.

제한 Hooks 실험에서는 사용자 요청과 두 역할의 시작/종료·공개 결과를 확인했지만 부모 Stop 누락이 남았다. 추가 시험·원인 확정·설정 변경은 보류다. 실제 식별자/원문/화면 증거는 공개하지 않는다. 시험 역할 활동을 일반 업무 성과와 합치지 않는다.

## 공개 기준 검증

공개 복사본에서 공식 npm HTTPS 등록소와 잠금 파일 integrity를 확인한 뒤 승인된 npm ci를 수행했다. 잠금 파일은 바뀌지 않았으며 22개 합성 단위·회귀 테스트, TypeScript 검사, Vite production 빌드가 모두 통과했다. 이전 복사 의존성의 플랫폼 불일치는 재설치 후 해소됐다. 기존 앱·실제 기록·파일 권한은 변경하지 않았다. 개인 데이터 없는 36개 공개 파일을 대상으로 staged 전체 내용과 비밀/식별 패턴을 검토했다. 자동 검사로 완전한 안전을 보증하지 않는다.

테스트 범위: 턴 경계, 내부 실행 제외, 비밀 마스킹, 질문 후보, 반복/검증 명령 근거, 선택 변경 지연 응답, Hooks allowlist/보관정책. 검증은 이 공개 코드 기준이며 실제 연결 재검증/전체 이력 기능 완료를 뜻하지 않는다. 과거 로컬 실제 업무 연결 확인은 새 설치에서의 연결 성공을 대신하지 않는다.

## 다음 순서 — 사용자 검토 후 선택

### 페이지 목적을 드러내는 HTML 검토안

사용자의 요청에 따라 `docs/prototype/index.html`을 시작으로 검토 홈·업무 이력·업무 상세·품질 검토·다음 요청 개선의 5페이지 정적 시안을 별도로 작성했다. 페이지별 질문·정보 배치·필요 데이터·완료 기준은 PLAN의 새 페이지 제안에 정리했다. 기존 wireframes와 실제 앱은 유지한다. 시안은 완전 합성 내용이며 실제 업무 연결·영구 평가 저장·자동 전송을 포함하지 않는다. 페이지 구성과 구현 범위는 아직 사용자 미확정이다.

이번 작업에서 기존 앱의 22개 테스트, TypeScript 검사와 Vite 빌드를 실행해 통과했다. 이는 정적 시안의 브라우저 검증을 대신하지 않는다. 브라우저 도구에서 file 프로토콜 접근이 정책상 차단되어 실제 렌더링 검증은 미실시다. 정적 링크·앵커·자산·ID와 JavaScript 문법을 점검했고, DOM 대역에서 검색·필터·턴 전환·평가 유효성·텍스트 미리보기 시연을 확인했다. 이는 실제 브라우저 배치·반응형 검증을 대신하지 않는다. 기존 localhost 서버는 종료·재시작하지 않았다.

1. PLAN과 wireframes의 전체 이력·진행 중·확인 필요·품질 검토 흐름 검토.
2. 한 업무의 완료조건과 품질 항목/사람 검토 방식을 확정.
3. 전체 턴 탐색과 수집상태 구분부터 범위가 작은 구현을 선택.
4. 역할 비교는 연결 증거·통제조건·표본이 확보된 후 검토.

이번 기준 저장소 정리는 새 기능 구현, Stop 재시험, 원격 접속, 공개 배포를 포함하지 않는다.
