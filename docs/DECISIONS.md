# 결정과 보류

## 사용자 확정

- 목표는 AI 사용의 품질 향상이다.
- README는 사용법, AGENTS는 AI가 참고할 목표/작업 기준, 기획 문서는 기능과 UI 검토 자료를 담당한다.
- 사용자가 기획과 UI를 검토하고 기능을 선택해 지시하면 그 범위를 개발한다.
- 공개 저장소에는 개인 정보·비밀·실제 업무 기록을 넣지 않는다. 기존 앱·원본 기록은 보존한다.
- 기본 앱은 localhost 관측 전용이다. 원격 노트북 접속은 미래 요구이며 이번에 구성하지 않는다.
- 문제가 생기거나 범위·권한·귀속이 애매하면 해당 단계를 멈추고 확인한다.

- 사용자 정의 역할 외의 일반 sub-agent 실행도 대시보드에서 검토한다. 역할명 허용목록 대신 실제 공개 실행 출처·관계 증거를 사용하며 내부 안전·승인·시스템 실행은 계속 제외한다. Hooks 실험 확대는 포함하지 않는다.

- 개발 중 별도 build/start 반복을 줄이도록 `npm run dev`에서 화면 자동 갱신과 API 코드 자동 재시작을 제공한다. production `build`/`start`는 기존대로 유지한다.

## 현재 기술 경계

- 공식 App Server 읽기 API와 제한된 프로젝트 Hooks 시험을 분리한다. 출처·관측 시각·누락을 표시하고 ID가 확인되지 않으면 합치지 않는다.
- 실행 종료≠품질 완료. notLoaded/idle/오프라인≠완료. 미제공≠0.
- 공식 승인 연결은 미지원이며 문장 후보는 미해결 여부 미확인. 대시보드에서 승인/거절/자동재개를 실행하지 않는다.
- 활성 훅·신뢰 설정·역할 정의·실제 데이터는 공개하지 않는다. 예제는 자동 활성화하지 않는다.

## 보류·미확정

- 부모 Stop 누락 원인 진단/재시험.
- 전체 진행 중 대화의 안전한 수집 방법과 전체 이력 저장 범위/보관기간.
- 품질 항목의 중요도·최종 승인 주체·평가 저장 방식.
- 품질 기준을 통과한 실행끼리 효율을 비교하는 원칙과 통제조건은 PLAN의 검토안.
- PLAN의 화면/평가 설계, ApprovalRequest 연결, 위임 비교 절차.

PLAN의 우선순위와 화면은 검토안이다. 사용자 확정으로 승격하려면 선택 범위·완료조건을 이 문서에 갱신한다. 임의로 종합점수나 역할 순위를 도입하지 않는다.
