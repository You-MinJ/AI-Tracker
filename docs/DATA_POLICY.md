# 데이터·개인정보 정책

## 공개 코드와 개인 실행 데이터 분리

저장소에는 코드, 패키지 잠금 파일, 비활성 예제, 완전 합성 테스트, 일반화된 문서만 둔다. 기존 비공개 Git 이력을 가져오지 않는다. 실제 업무 데이터는 복제/커밋 대상이 아니다.

공개 금지: 사용자 홈/프로젝트 실제 경로, 이메일/연락처, 실제 지시/결과/agent·thread·session ID, 화면 캡처, 이벤트·JSONL·로그·DB, 내부 검토 보고서, 인증/세션 파일, .env·키·토큰, node_modules/dist, 전역 역할/AGENTS/config, 개인 백업. 실제 시험 증거는 기술적 한계로만 요약한다.

.gitignore는 방어의 일부일 뿐이다. 커밋 전에 staged 목록과 전체 diff를 사람이 읽고 check:public 검사를 수행한다. 검사 도구는 값 대신 발견 파일/범주만 보고한다. 합성 비밀 형식은 테스트 경계 안에서만 허용한다. 자동 검사로 모든 비밀/개인정보 탐지를 보장하지 않는다. 작성자·커미터 이메일은 확인된 GitHub noreply만 사용한다.

## 런타임 출처

- App Server 공식 읽기 allowlist: initialize, thread/list/read, thread/turns/list, thread/items/list, account/rateLimits/read, account/usage/read. 로컬 앱은 지원 API의 필요한 공개 업무 메타데이터/항목만 읽는다. 인증·세션 원본을 직접 읽지 않는다. CLI 자체는 기존 계정으로 공식 서비스 통신을 할 수 있다.
- 기본 앱에는 App Server 대화의 별도 영구저장/내보내기 기능이 없다. 브라우저·서버 메모리에서 표시 한도/마스킹을 적용한다. 외부 CDN·분석 도구·호스팅으로 보내지 않는다.
- Hooks는 선택적 실험이다. 활성 .codex/hooks.json은 공개본에 없으며 예제 검토·프로젝트 신뢰·별도 동의가 필요하다. 공개 예제 복사만으로 자동 수집하지 않는다.

## 제한 Hooks 정책

UserPromptSubmit/SubagentStart/SubagentStop/Stop 네 종류만. 프로젝트 경로와 마커 등록 세션, 허용 역할을 검사한다. 식별자·역할·모델·수신시각, 최대4000자의 마스킹한 요청/공개 결과만 저장한다. 도구 입력/응답/메타데이터, transcript 경로·파일, 비공개 추론/내부 안전검토, 원시 payload는 제외한다. 모델/역할이 없거나 불분명하면 추정하지 않는다.

저장 위치는 실행 프로젝트 내부 data/events. 수집기가 만든 owner/prefix·UID·일반파일 조건을 만족하는 파일만 14일 정리한다. 원본/다른파일/심볼릭링크는 정리하지 않는다. 정리는 collector 실행 시 수행하므로 미실행 기간에 정확히 14일째 자동 삭제되는 타이머는 아니다. 시험용 세션 registry도 같은 보존 범위를 따른다. 범위/기간 확대나 영구 이력 저장은 새 동의와 설계가 필요하다.

훅은 관찰만 하며 승인·허용 변경·추가 모델 호출·작업 연장/중단 지시를 하지 않는다. 오류 시 raw 입력을 출력하지 않는다. 부모 Stop 누락 원인은 미확정이며 재시험은 보류다.

## 표시·네트워크 경계

React escaped 텍스트로 렌더링, HTML/스크립트 실행 금지. 중첩 JSON/비밀키 패턴/Bearer/개인 연락처를 마스킹하고 길이를 제한한다. 완전한 익명화로 보증하지 않으므로 민감 업무를 공개하지 않는다. 결과 HTTPS 링크는 안전 조건과 사용자 클릭으로만 열고 로컬 산출물은 경로 표시만 한다.

서버는 127.0.0.1만, 정확한 Host/Origin·GET·cross-site 검사, CSP/no-store/no-referrer. 임의 파일·셸 실행·승인·변경 API 없음. 인증이 없는 로컬 앱이므로 같은 컴퓨터의 다른 프로세스/사용자까지 완전히 격리하는 보안 제품은 아니다. 원격 노출은 별도 인증·접근정책 설계 전까지 하지 않는다.

실행상태/수집상태/품질을 분리하고 누락은 미확인으로 표시한다. 내부 안전심사와 숨겨진 추론은 목록·상세·검색·집계에서 제외한다. 향후 ApprovalRequest는 공개 요청 추적만이며 공식승인/자동재개가 아니다.
