# 기능·품질·UI 기획 검토안

아래 내용은 **검토용 제안**이며 사용자 확정·구현 완료가 아니다. 현재 구현은 CURRENT에 구분한다. 화면 초안은 [wireframes.html](wireframes.html)이며 모든 사례는 합성이다.

## 제품이 답해야 할 질문

“무엇을 맡겼나 → 어떤 결과를 받았나 → 무엇으로 검증했나 → 어디를 고쳤나 → 이 역할·위임 방식이 가치가 있었나?”

목표 단위는 전 작업→전체 턴→부모/하위 실행→지시/공개 결과/검증 증거다. 각 노드는 source/thread/turn/agent 관계와 관측 구간을 유지한다. 같은 역할명의 다른 실행을 영구 직원 하나로 합치지 않는다. 역할 정의/버전/모델과 실행 인스턴스는 별도이며 미제공이면 표시한다. 현재 전체 이력 영구저장 구현은 없다.

## 제안하는 첫 기능과 완료조건

| 검토 순서 | 기능 | 필요한 데이터와 완료조건 |
|---|---|---|
| P1 | 전체 이력 탐색 | 업무별 모든 조회 가능한 턴을 시간순 탐색. 페이지/누락 범위 표시. 각 턴 지시와 해당 결과만 연결. 홈 최신 턴과 과거 턴을 구분 |
| P1 | 진행 중·수집 상태 분리 | 실행상태와 lastSeen/source/수집상태 독립 표시. 미관측을 완료로 바꾸지 않음. 진행 중 미표시 원인을 공급 범위와 UI 문제로 분리 검증 |
| P1 | 품질 검토 카드 | 업무 시작 기준·완료조건, 산출물·검증 증거, 사람 검토와 미해결 항목을 연결. 최종 메시지만으로 통과 금지 |
| P2 | 수정·재작업 이력 | 사용자 명시 수정요청과 해당 변경/산출물 연결. 일반 후속질문을 수정으로 추정하지 않음. 채택/수정/폐기는 사람 기록 또는 명시 증거만 |
| P2 | 역할-업무 적합성 | 업무 유형별 사례, 역할/모델/조건/표본, 채택·수정과 재작업 근거. 표본 부족 표시, 자동 순위 없음 |
| P3 | 위임 가치 비교 | 통제된 단독/위임 사례 비교. 품질 기준을 통과한 실행끼리 효율 비교 |
| 별도 확인 | ApprovalRequest | 공식 API로 확인한 요청의 대상/시각/상태/원래 대화 연결. 표시·추적만 하며 공식승인·자동재개 아님. 미연결은 ‘대기 없음’ 아님 |

어떤 순서를 구현할지 사용자가 검토한다. 외부 수집 확대나 원격 접근은 별도 설계·동의가 필요하다.

## 품질 평가 제안 — 점수 대신 근거

**성과 품질**과 **과정 가시성**을 분리한다. 각 항목은 `미충족 / 부분 충족 / 충족 / 평가 불가`로 시작하며, 근거 링크·검토자·검토시각·기준 버전을 남기는 방안을 제안한다. 종합점수·자동 가중치는 보류한다.

| 구분 | 항목 | 검토 근거 |
|---|---|---|
| 성과 품질 | 요구 충족 | 원 지시/범위와 산출물 비교 |
| 성과 품질 | 정확성 | 테스트·원자료 대조·전문가/사용자 검토 |
| 성과 품질 | 실사용 가능성 | 실제 사용 흐름·재현·운영 조건 확인 |
| 성과 품질 | 완료조건 | 사전 합의한 기준별 충족 여부 |
| 과정 가시성 | 지시–결과 연결 | 같은 업무/턴·실제 부모자식 연결 증거 |
| 과정 가시성 | 검증 근거 | 에이전트 보고와 공개 도구 결과 구별 |
| 과정 가시성 | 관측 누락 | 미수집 구간·페이지·오프라인·최종 확인시각 |
| 과정 가시성 | 승인 준수 | 명시 허용 범위·확인 요청과 실제 수행 대조; 내부 심사는 수집하지 않음 |

“평가 불가”는 실패가 아니며 검증 명령 exit0은 그 명령의 근거일 뿐 업무 품질 전체를 보증하지 않는다. 사람의 채택/수정 판단을 자동으로 생성하지 않는다.

## 품질 통과 후 효율 비교 제안

같은 업무유형/난이도, 동일한 완료조건·입력자료·모델/설정·관측범위가 있는 사례만 비교한다. 표본수, 누락, 평가자와 조건 차이를 함께 보여준다. 작은 표본으로 역할 성능을 일반화하지 않는다.

단독 수행 대비 위임은 하위 실행 시간뿐 아니라 **분배·대기·통합·재검증**과 사용자 검토·재작업 시간을 포함한다. 병렬 실행의 합산 시간과 실제 경과시간을 구분한다. 토큰/비용은 공식 원값과 포함 범위가 확인될 때만 사용한다. 없는 값을 추정하지 않는다. 위임 역할의 기여는 산출물 채택·수정과 유형별 재작업 사례로 검토하며 빠름만으로 좋은 직원이라고 판단하지 않는다.

## 화면 흐름

전체 이력(기본 진입 제안) → 업무 타임라인 → 선택 턴의 지시/수행/결과/검증 → 품질 검토 → 사용자 결정/수정 항목. 진행 중·확인 필요는 독립 탐색 탭이다. 역할 사례는 검토한 업무에서 연결한다.

- 전체 이력: 프로젝트·기간·수집범위 검색, 최근 결과만이 아닌 턴 목록, 페이지 추가와 누락 배지.
- 진행 중: 실행상태·수집상태·마지막 관측을 따로 표시. 새 이벤트 없음은 실행 종료 아님.
- 확인 필요: 공식 요청 / 최종 문장 후보 / 사람 검토 할 일을 분리. 미연결 배너와 원래 대화 안내. 승인 실행 버튼 없음.
- 품질 검토: 원 지시/완료조건과 산출물/검증을 나란히 비교. 성과 품질과 과정 가시성의 항목별 근거. 사람 판단 저장은 향후 선택 기능임을 명시.
- 역할 사례: 역할 정의 미제공과 실행 ID 구별, 유형별 사례·수정·채택, 조건/표본수 배지. 데이터 부족이면 비교 근거 부족.

## 빈·오류·미수집 상태 완료조건

| 상태 | 화면 제안 |
|---|---|
| 조회 전 | 연결 확인 중, 개수 미확인. 0건/대기없음으로 단정하지 않음 |
| 성공한 빈 범위 | ‘이 조회 범위에 기록 없음’, 필터 초기화와 출처 표시 |
| 오프라인/오류 | 마지막 성공 시각과 보존 화면, 현재 상태 미확인, 재조회 |
| 미수집/잘린 페이지 | 수집 시작 이후/일부 페이지 배지, 없는 결과를 이전 턴에서 가져오지 않음 |
| 실행 중·공개결과 없음 | 진행 관측 근거와 마지막 관측 시각. 숨겨진 추론을 대신 표시하지 않음 |
| 승인 미연결 | 연결 미제공. ‘대기 없음’ 금지 |
| 품질 미평가 | 평가 불가/검토 전. 완료 메시지로 자동 통과 금지 |

## 이후 구현 검증 제안

서로 다른 실제 업무 최소3개에서 전 턴 탐색/관계/지시·결과 경계를 확인하되 공개 저장소에 원문을 남기지 않는다. 합성 회귀로 빈/오프라인/미수집/실패/긴 항목/지연 A→B/악의적 HTML/비밀 패턴을 검사한다. 화면 검토와 작은 구현 단위마다 CURRENT·DECISIONS를 갱신한다.
